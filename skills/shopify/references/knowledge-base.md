## Theme development
- Theme folders, each with a fixed job: `layout/` (outer wrappers e.g. `theme.liquid`, wraps every page — load global assets/scripts before `</body>`), `templates/` (page templates; Online Store 2.0 = JSON e.g. `index.json`), `sections/` (reusable page units, `.liquid`), `snippets/` (small reusable chunks, rendered via `render`, accept params), `assets/` (CSS/JS/images), `config/` (theme settings), `locales/` (translation `.json`) (src: TA 42a1716f).
- A section file = implementation markup on top + a `{% schema %}` JSON block at the bottom defining `name`, `settings`, `blocks`, and `presets` (a preset makes the section selectable in the Theme Editor) (src: TA 42a1716f).
- Every setting object needs at least `type`, `label`, and `id`; read the value in Liquid via `section.settings.<id>` or `block.settings.<id>` (src: TA 42a1716f).
- Sections = whole-unit config (e.g. slideshow speed); blocks = child items merchants add/remove/reorder (slides, FAQ rows). Section + block config is stored in the page's JSON template, not the section file (src: TA 42a1716f).
- Next-gen **theme blocks** (Horizon foundation) live in a top-level `blocks/` dir and are reusable across sections; declare block types as `@theme` in schema and render with `{% content_for "blocks" %}`; support nesting (source: up to ~8 levels), often paired with metaobjects (src: TA 42a1716f, TA 0e415048).
- Liquid is **server-side only** — fully evaluated before the page loads; no Liquid reaches the browser. Rule of thumb: Liquid does things before load, JavaScript after (user interaction) (src: TA 345b2b20, TA 2dcff631).
- To pass server data to client JS, emit a hidden `<script type="application/json">` via a Liquid loop, then `JSON.parse(document.querySelector('#id').textContent)`. Sensitive lookups (e.g. metafields) must be done in Liquid, never trusted to user-editable JS (src: TA 2dcff631).
- **Section Rendering API**: update parts of a page without full reload — `fetch` with `?section_id=<name>` (single) or `?sections=` (multiple); re-executes that section's Liquid in new context and you swap the returned HTML. Dawn 15+ uses this for variant switching instead of hidden-script matching (src: TA 345b2b20, TA 96ca7b02).
- Decouple JS with a **pub/sub** event system (Dawn 15+): `publish(pubSubEvents.<event>, data)` / `subscribe(...)`, event names held as constants in `constants.js` to avoid typos (src: TA 3055bc10).
- Performance: prefer **vanilla JS over jQuery/heavy libs**; keep images under ~200KB in `.webp`/`.jpeg`; avoid autoplay video on mobile; uninstall unused apps (residual injected code slows the storefront) (src: TA 4e579a94, TA 5e257dd0).

## Theme development workflow (git / safe editing)
- Never edit code directly on a live theme — duplicate the theme (or work on a side branch) and publish only after testing (src: TA 2dcff631, TA 271d27b4).
- Connect the store's live theme to a repo `main` branch via Shopify's **GitHub integration**: pushes to `main` go live instantly, and Theme Editor/customizer changes sync back as commits. Build features on side branches locally with the **Shopify CLI**, then PR into `main` to deploy (src: TA 77b348b8).

## Theme Store submission (verify current bar at shopify.dev)
- Building for the Theme Store ≠ a one-client theme: it must work across many merchant setups and regions, including native **right-to-left (RTL)** support and extreme flexibility across business types/catalog sizes (src: TA 9ee7614d, TA e6562521).
- Must **integrate cleanly with App Store apps** without breaking layout or needing manual code patches (src: TA de43c8ca).
- **Mobile-first** is enforced — seamless mobile checkout and cart-drawer experience (src: TA 2c13a357, TA cd47eb52).
- Code-quality bar: clean, well-structured, extensible codebase; vanilla JS preferred over jQuery (src: TA de43c8ca, TA 4e579a94).
- Accessibility is increasingly mandatory — e.g. proper image **alt text** across product/media (src: TA fe37927c, TA 6e1e5916). Dawn is a Shopify-maintained, clean, fast reference base (Craft/Sense/Taste/Crave are Dawn variants) (src: TA de43c8ca). NOTE: sources gave no exact Lighthouse/theme-check numeric thresholds — pull those from shopify.dev.

## App development
- Three extensibility models: **embedded apps** (your server, rendered in admin via iframe), **UI extensions** (checkout/POS/customer-account — render at predefined "extension targets" instead of editing theme files), and **Shopify Functions** (custom backend logic — pricing, discounts, cart-transform — that run inside Shopify's infra, not your server) (src: TA 540f17f0, TA ab3ffc73, TA 265911f0).
- Next-gen dev platform: `shopify app dev` previews live on dev stores with hot-reload of scope/webhook/extension changes, runs on **localhost** (no tunnels). Define custom data (metafields/metaobjects) **declaratively in the app `.toml`** — on deploy Shopify instantiates the schema across every installed store, replacing post-install hooks (src: TA b7e32bb4, TA 050f9d61).
- **Polaris unified web components** are consistent across surfaces (admin/checkout/customer-accounts/POS), delivered via App Bridge off Shopify's CDN (auto-updates, no npm bump), and framework-agnostic (React/Vue/none). Polaris is **recommended but not required** for the Build for Shopify (BFS) badge (src: TA 050f9d61, TA b7e32bb4).
- APIs: **GraphQL Admin API** is the path forward — the REST Admin API for products/variants is deprecated in its favor; treat API stability as sacred (breaking APIs creates "invisible work") (src: TA fe57fbc4, TA b2a247a3). Storefront API has no rate limit (built for high-traffic custom storefronts) but can't do admin actions (src: TA 265911f0).
- GraphQL Admin API uses a **cost/points** budget per query by complexity; source cites standard plans ~100 points/sec, Shopify Plus ~1,000/sec — throttle loops over large catalogs (src: TA b145c203). Verify current limits at shopify.dev.
- Checkout UI extensions can read app-owned metafields at checkout; POS UI extensions now get **direct Admin API access** (no backend proxy) (src: TA b7e32bb4). Draft orders now work with bundles/deposits/vaulted cards and honor Functions + checkout extensions (src: TA dbcbafb7, EC 3a2feb4a).
- App Store growth: the algorithm favors newer apps using modern/trending features (e.g. AI) over tenure; ~10 early reviews can snowball category ranking. BFS badge = Shopify's top quality standard (src: TA fe37927c, TA fe57fbc4, TA 6e1e5916). NOTE: sources did not cover the Billing API or the full listing-review checklist — get those from shopify.dev.

## Store setup & merchandising
- Product listing fields: descriptive title, benefit-focused description, 3–5 quality images from multiple angles (+ video/3D models), price, compare-at price, cost-per-item, inventory (SKU + track-quantity), shipping weight, and the search-engine listing (page title / URL handle / meta description) (src: EC c95e90e8, EC 8b89353e, EC 9ae4eeb6).
- Variants consolidate size/color/material/region into one listing — Shopify raised the historical variant cap (source figure is garbled; confirm the current per-product limit at shopify.dev) — splitting products to dodge old limits hurts SEO and inventory hygiene (src: EC 49d746eb, EC bbd6392d).
- **Collections**: manual (hand-pick products) vs automated/"smart" (rules on tag, product type, price, inventory). Name/describe them well for navigation + SEO (src: EC 8b89353e, EC 9ae4eeb6).
- **Metafields/metaobjects** = Shopify's core extensibility (JSON-column-like custom data on products/customers/orders); define declaratively so updates propagate across stores. Metaobjects can drive auto-generated page templates (one template → a page per entry) (src: EC 1d594a7a, EC 3388c5ea, EC 8b89353e).
- **Navigation**: main menu = broad categories, nest submenus by dragging items right; footer menu = legal/trust pages (shipping, refund/return, privacy, terms). Consider mega menus (large catalogs), breadcrumbs, and the free **Search & Discovery** app (predictive search + custom synonyms so "trainers" finds "sneakers") (src: EC 8b89353e, EC 77e84521, EC e8bba8d7).
- **Shopify Markets**: designate primary + secondary markets by grouping countries; buyers outside an active market are blocked at checkout. Markets auto-handle localized payments, currency, duties/import taxes, and tax-inclusive vs tax-exclusive display per region (src: EC 191d5985, EC 77e84521, EC c5ef18bb, EC c149a400).
- **Agentic/catalog syndication**: Shopify Catalog structures product data so it syndicates to AI surfaces (ChatGPT/Copilot/Perplexity/Gemini) via Agentic Storefronts; a universal product ID clusters same-SKU items to cut duplicates. Group products by attributes/metafields and keep the Knowledge Base app answers current so agents present you accurately (src: EC 49d746eb, EC b1726cd3, EC 5fd86fe0).

## Shopify-specific conversion & retention
- PDP: 3–5 zoomable images + video/3D, benefit-led descriptions, social-proof review apps (Judge.me / Loox), trust/secure-payment badges, a **sticky Add-to-Cart**, and native low-stock ("only 3 left") signals. Horizon-foundation cart drawers use interactive product cards + quick-add (src: EC 8b89353e, EC e8bba8d7, EC 76df8cce).
- **Checkout**: Shopify collapses multi-step checkouts toward a single-step flow (case cited: 5-step → 1-step, 2.8s → 0.8s). Inject **Checkout UI extensions** (e.g. brand-promise list beside payment) and back them with metaobjects/app metafields so they're admin-configurable, not hardcoded (src: EC c1fd6493, EC 3388c5ea).
- **Accelerated checkout**: enable Shop Pay + Apple Pay + Google Pay + PayPal to kill the "type your card" friction; Shop Pay is cited as one of the highest-converting checkouts (one-click for returning buyers) and now shows the saved card's last-4 to cut checkout anxiety (src: EC e8bba8d7, EC b1726cd3, EC 49d746eb). Offer guest checkout — forced account creation is a major drop-off (src: EC 8b89353e).
- **Upsell / recurring / cross-sell**: subscriptions via Shopify's free subscription app or third-party (e.g. Subify); the **Shopify Product Network** cross-sells non-competing partner products (search/collection/post-purchase placements) for commission, US + Shopify Payments + Shop Pay required, with competitor exclusions (src: EC 76113218, EC 8b89353e, EC 49d746eb, EC d90c104d).
- **Abandoned-cart recovery** (built-in, free even past email caps): default "Recover abandoned checkout" automation sends a pre-filled cart link; cited cadence — 1st email ~1hr after abandonment, follow-up ~24hr; add discount/free-shipping incentives; also recover add-to-cart-then-bounce; system auto-excludes anyone emailed in the last 14 days. Escalate high-value carts via Shopify Flow (e.g. WhatsApp) (src: EC e8bba8d7, EC 7c0712d3, EC 8b89353e).
- **Omnichannel**: POS "Send Cart" emails an in-store shopper their cart; the later online sale attributes back to the store/associate — closes the retail→online loop (src: EC f4e41a93, EC 0bab000f).
