## Critique Strategy

```text
Review the proposed output adversarially before accepting it.

Check for:
1. Duplicate systems or parallel authorities.
2. Security, privacy, or secret-handling drift.
3. Missing validation, rollback, or proof boundaries.
4. Scope expansion beyond the requested slice.
5. Claims that are not backed by a file, command, log, endpoint, or explicit source.

Lead with defects. If no defect is found, state the residual risk and the narrow evidence
that supports acceptance.
```
